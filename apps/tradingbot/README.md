# Демо-бот: шорт истощения импульса на альткоин-фьючерсах

Бот берёт **настоящие** данные с Bybit (фьючерсы USDT-перпетуалы), сам ищет монеты
под торговую стратегию и в момент точки входа **записывает** фейковую сделку:
«вот здесь я бы зашёл в шорт, вот здесь бы вышел». Реальные ордера не отправляются
никуда и API-ключи не нужны — используется только публичный рынок.

## Установка

```powershell
pip install -r requirements.txt
```

Нужен Python 3.10+.

## Запуск

```powershell
python run.py            # демо-торговля в реальном времени
python run.py --web      # то же + веб-панель на http://localhost:8080
python run.py report     # сводка по журналу сделок
python run.py selftest   # проверка логики на синтетических свечах, без сети
```

Полезные ключи:

```powershell
python run.py --margin 20 --leverage 20 --stop 5 --take 15
python run.py --min-change 0.15 --max-positions 5
python run.py --no-orderbook --debug
```

Остановка — `Ctrl+C`, бот напечатает итог сессии.

## Что появляется в `data/`

| Файл | Что внутри |
|------|-----------|
| `trades.csv` | закрытые сделки: №, дата, монета, ТФ, время входа/выхода, цены, стоп, тейк, комиссия, **профит в $**, причина выхода |
| `signals.csv` | все сработавшие сетапы, включая пропущенные (и почему пропустили) |
| `state.json` | что бот наблюдает прямо сейчас, открытые позиции, статистика |
| `bot.log` | полный лог работы |

`trades.csv` — с разделителем `;` и BOM, открывается в Excel двойным кликом.

## Торговая стратегия

**1. Отбор монет** (`bot/scanner.py`)
- USDT-перпетуалы, рост за 24ч > 10% (и < 300%, чтобы не лезть в пустые пампы);
- альткоин: BTC, ETH, стейблы и плечевые токены исключены;
- средние объёмы: оборот 3M–250M $ за сутки;
- рост именно резкий: ≥45% дневного движения сделано за последние 4 часа;
- листингу больше 7 дней.

**2. Импульс** (`bot/strategy.py: find_impulse`) — на 1m, 5m и 15m ищется окно из
4–12 свечей, где:
- суммарный рост выше порога ТФ (1m: 2%, 5m: 3.5%, 15m: 5.5%);
- откаты внутри импульса ≤ 35% от всего движения, красных свечей ≤ 1/3,
  ни одна свеча не проваливается ниже начала импульса — то есть рост «без просадок»;
- объём в импульсе ≥ 1.4× фонового.

Нужно подтверждение минимум на 2 таймфреймах из 3.

**3. Точка входа — «затуп»** (`find_stall`). Импульс должен начать тухнуть; проверяются
5 признаков, требуется минимум 3:
- свечи сузились (диапазон < 60% среднего по импульсу);
- объём упал (< 75% пика импульса);
- появились верхние тени (≥ 35% диапазона свечи);
- последние свечи не обновляют хай импульса;
- скорость роста упала более чем вдвое от пиковой.

Если цена уже упала от вершины больше 2% — вход отменяется, поезд ушёл.

**4. Сделка** (`bot/paper.py`) — шорт на **20 $ маржи с плечом x20** = позиция 400 $.
- стоп-лосс — цена, на которой чистый убыток равен **5 $** (≈ +1.2% против нас);
- тейк-профит — **+15 $** (≈ −3.8% по цене);
- комиссия тейкера 0.055% в обе стороны заложена в уровни, чтобы −5$ и +15$ были
  именно чистыми;
- безубыток: после +6 $ стоп подтягивается к цене входа.

**Выход «прогноз не сбылся»**: если цена сходила вниз, но вернула ≥55% достигнутого
хода — закрываемся, не дожидаясь стопа. Терпение зависит от ведущего таймфрейма —
чем он старше, тем на более долгое падение мы рассчитываем:

| ТФ | ждём реакции | максимум в позиции |
|----|--------------|--------------------|
| 1m | 4 мин | 12 мин |
| 5m | 15 мин | 45 мин |
| 15m | 45 мин | 150 мин |

**5. Стакан** (`bot/orderbook.py`). Бот опрашивает стакан раз в секунду и ведёт историю
по каждому ценовому уровню, чтобы отличить настоящую плотность от спуфера:

- плотность = уровень, чей объём в 6+ раз больше медианного в зоне ±1.5% от цены;
- **настоящей** она считается, только если прожила ≥6 опросов подряд и не усохла
  более чем на 45% от своего максимума;
- если крупная заявка исчезла рано или испарилась при подходе цены — это спуфер,
  он не влияет на решения и попадает в счётчик `spoof`.

Реакция бота:
- настоящая **ask**-стена сверху = сопротивление → плюс к скору шорта;
- настоящая **bid**-стена ближе 0.6% под ценой → **вход запрещён**;
- bid-стена дальше → минус к скору;
- перекос стакана в сторону покупателей > 1.8× → вход запрещён;
- если в открытой позиции под ценой встала настоящая bid-стена, а мы в плюсе —
  фиксируем прибыль, не дожидаясь тейка.

Итоговый скор сетапа = 0.45×импульс + 0.25×подтверждения ТФ + 0.30×затуп ± стакан.
Порог входа — 0.55 (`entry.min_setup_score`).

## Настройка

Всё в `bot/config.py`, по разделам: `ScreenerConfig`, `ImpulseConfig`, `EntryConfig`,
`RiskConfig`, `ExitConfig`, `OrderbookConfig`. Логика стратегии в код не зашита числами —
меняй конфиг.

## Веб-панель и сервер

`python run.py --web` поднимает страницу с журналом торговли на `:8080`
(таблица сделок, открытые позиции, статистика, хвост лога, скачивание CSV).
Данные она берёт из тех же файлов в `data/`, отдельная база не нужна.

Развёртывание в Docker/Kubernetes и описание всех эндпоинтов — в
[setupToServer.md](setupToServer.md). Готовые `Dockerfile`, `docker-compose.yml`
и `k8s/tradingbot.yaml` лежат в корне проекта.

## Структура

```
run.py              запуск, CLI, отчёт
bot/config.py       все параметры ТС
bot/exchange.py     публичный REST-клиент Bybit v5
bot/scanner.py      шаг 1: отбор монет
bot/strategy.py     шаги 2-3: импульс и затуп
bot/orderbook.py    шаг 5: плотности и анти-спуфинг
bot/paper.py        шаг 4: демо-исполнение, стоп/тейк/выходы
bot/journal.py      CSV-журнал и state.json
bot/engine.py       циклы: сканер, поиск сетапов, ведение позиций
bot/web.py          веб-панель и HTTP-API
tests/selftest.py   проверка логики без сети
Dockerfile          образ для сервера
k8s/tradingbot.yaml манифесты Kubernetes
```

## Важно

Это симулятор на реальных котировках, а не гарантия результата. Демо-исполнение
считает вход и выход по последней цене без проскальзывания и без учёта того, что
на тонком альткоине позицию в 400 $ рынок двинет. На реальных деньгах результат
будет хуже — сначала набери статистику в `trades.csv`.
